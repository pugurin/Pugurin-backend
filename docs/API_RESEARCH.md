# 외부 API 조사 결과 (이슈 #3)

실제 키로 응답을 받아 확인한 내용입니다. 조사일 2026-10-06, 표본은 해운대구·수영구(+일부 16개 구·군) 2025년 7~9월입니다.
**확인한 것**과 **아직 확인하지 못한 것**을 구분해서 적었습니다.

## 1. 키·접근 현황

| 대상 | 상태 | 비고 |
|---|---|---|
| 공공데이터포털 매매 4종 (아파트·오피스텔·연립다세대·토지) | 정상 | 매매용 키 |
| 공공데이터포털 전월세 3종 (아파트·오피스텔·연립다세대) | 정상 | **전월세용 키가 따로 발급**됨. 오피스텔 전월세는 처음 호출에서 403이었다가 이후 정상 |
| 카카오 로컬(지오코딩) | REST 키로 동작 | JS 키는 서버에서 못 씀. 약관(저장·타사 지도 표시) 미확인 |
| VWorld | **사용하지 않음** | 토지이용계획·토지특성·연속지적도·중개업자 조회의 공급처가 없어짐 |
| 국세청 사업자 상태조회, 건축물대장 | **미확인** | 키 미수령 |

## 2. 실거래가 7종 요청 규격

- Base `https://apis.data.go.kr/1613000/<서비스>/<오퍼레이션>`, 응답은 **XML**.
- 파라미터: `serviceKey`, `LAWD_CD`(시군구 5자리), `DEAL_YMD`(YYYYMM), `pageNo`, `numOfRows`. `numOfRows=1000`은 동작함(최댓값은 미확인).

| 종류 | 서비스/오퍼레이션 |
|---|---|
| 아파트 매매(상세) | `RTMSDataSvcAptTradeDev/getRTMSDataSvcAptTradeDev` |
| 아파트 전월세 | `RTMSDataSvcAptRent/getRTMSDataSvcAptRent` |
| 오피스텔 매매 / 전월세 | `RTMSDataSvcOffiTrade/getRTMSDataSvcOffiTrade` / `RTMSDataSvcOffiRent/getRTMSDataSvcOffiRent` |
| 연립다세대 매매 / 전월세 | `RTMSDataSvcRHTrade/getRTMSDataSvcRHTrade` / `RTMSDataSvcRHRent/getRTMSDataSvcRHRent` |
| 토지 매매 | `RTMSDataSvcLandTrade/getRTMSDataSvcLandTrade` |

**응답 동작**
- 정상: HTTP 200 + `resultCode=000`. 금액은 만원 단위에 천 단위 쉼표(`144,000`).
- **데이터가 없으면 에러가 아니라 빈 목록**(`<items/>`, `totalCount=0`)이다. 미래월, 과거월, **존재하지 않는 지역코드(`99999`)**, 페이지 초과가 모두 같은 응답이라 서로 구분할 수 없다.
- 오류: 키 미등록은 HTTP 403 + `<OpenAPI_ServiceResponse>`(`returnReasonCode=30`). 한도 초과는 코드 22로 알려져 있으나 **실제로 한도를 넘겨 확인하지는 않았다**(코드 매핑은 공식 코드표 기준으로 구현, 한도 초과 응답 자체는 미검증).

## 3. 종류별 제공 필드

| 필드 | 아파트 매매 | 아파트 전월세 | 오피스텔 | 연립다세대 | 토지 |
|---|---|---|---|---|---|
| 단지 식별자 `aptSeq` | **100%** | **100%** | 없음 | 없음 | 없음 |
| 법정동 코드 `umdCd` | **제공** | 없음 | 없음 | 없음 | 없음 |
| 법정동명 `umdNm` | 제공 | 제공 | 제공 | 제공 | 제공 |
| 지번 | 제공 | 제공 | 제공 | 제공 | **가려짐(`8**`)** |
| 건물명 | `aptNm` | `aptNm` | `offiNm` | `mhouseNm` | 없음 |
| 해제 `cdealType`/`cdealDay` | 제공(7%) | **없음** | 매매만(10%) | 매매만(7%) | 필드는 있으나 표본 0건 |
| 중개/직거래 `dealingGbn` | 제공 | **없음** | 매매만 | 매매만 | 제공 |
| 계약 구분 `contractType`(신규/갱신) | - | 제공(갱신 15%) | 제공(갱신 6%) | 제공(갱신 10%) | - |
| 등기일 `rgstDate` | 91% | - | - | 83% | - |

- 전월세는 월세가 0이면 전세다(아파트 전월세 689건 중 322건, 47%).
- 아파트 전월세는 갱신 계약의 직전 보증금(`preDeposit`)과 갱신요구권 사용 여부(`useRRRight`)를 준다.
- 연립다세대에는 대지권 면적 `landAr`(100%)과 `houseType`(연립·다세대)이 있다.
- 토지는 `jimok`(지목), `landUse`(**용도지역**), `dealArea`(거래면적), `shareDealingType`(지분거래 표시)이 있다.

## 4. 설계에 영향을 주는 사실

### 4.1 토지는 지번이 전부 가려진다
해운대구 99건, 기장군 206건(2025-07~09)이 **모두 마스킹**이었다. 따라서 토지 거래는 필지 좌표를 만들 수 없고 `location_precision=dong`(법정동 중심점)으로만 둔다. **지도의 필지 마커는 실데이터에서는 거의 나오지 않는다** (다른 구에서는 확인하지 않았다). 프론트 디자인의 "토지 필지 마커"는 재검토가 필요하다.

### 4.2 토지 통계는 거르지 않으면 의미가 없다
해운대구+수영구 2025-09 토지 45건 중 **지분거래 28건, 지목 '도로' 24건**이고, 둘을 모두 뺀 거래는 **7건**이었다. 직거래도 약 절반(23건)이다. 기본 통계에서 지분거래·도로를 제외할지, 표본 수를 어떻게 표시할지 정해야 한다. 1개월 한 구 표본이라 일반화는 이르다.

### 4.3 해제·정정은 같은 행에 표시되거나 행이 바뀐다
- 해제는 별도 행이 아니라 **원래 거래 행에 `cdealType`/`cdealDay`가 붙는다**(아파트 9월 해운대구 32건). 해제 때문에 자연키가 바뀌지는 않는다.
- 금액·면적 정정은 행의 내용이 바뀌므로 **키가 바뀐 것처럼** 보인다. 최근 3개월을 재수집하고, 더 이상 오지 않는 행은 삭제 표시한다(`docs/ERD.md`).
- 전월세에는 해제 필드가 없다.

### 4.4 단지 식별자는 아파트만 있다
오피스텔·연립다세대는 (시군구, 법정동명, 지번, 건물명)으로 직접 묶어야 한다. 같은 지번에서 건물명이 다르게 오면 다른 단지로 갈라질 수 있다.

### 4.5 법정동은 코드표가 따로 필요하다
- 아파트 매매만 `umdCd`를 주고(`sggCd + umdCd` = 10자리 법정동 코드), 나머지는 **이름만** 준다.
- 이름은 157종(아파트·토지, 1개월)이고 **기장군은 리 단위까지 온다**(`기장읍 교리`, `일광읍 동백리`). `부평동4가`, `대저1동`처럼 번호가 붙은 이름도 있다.
- 따라서 (시군구, 법정동명) → 법정동 코드 매핑에는 **행정표준코드 법정동 코드 마스터**가 필요하다(출처·확보 방법 미정).

### 4.6 좌표는 어디에도 없다
7종 모두 좌표가 없어서 지오코딩이 필수다. 카카오 REST로 "부산 해운대구 우동 1407" → 경도 129.1450, 위도 35.1566을 받았다(동작 확인). 저장 가능 여부와 다른 지도 표시 가능 여부는 약관 확인 전이다.

## 5. 데이터 규모와 호출량 (2025-09, 부산 16개 구·군)

| 종류 | 월 건수 | 가장 많은 구 |
|---|---|---|
| 아파트 전월세 | 5,594 | 기장군 1,048 |
| 아파트 매매 | 3,395 | 해운대구 491 |
| 오피스텔 전월세 | 2,054 | 부산진구 477 |
| 연립다세대 전월세 | 1,144 | 수영구 234 |
| 연립다세대 매매 | 393 | 부산진구 99 |
| 토지 매매 | 364 | 기장군 79 |
| 오피스텔 매매 | 332 | 연제구 97 |
| **합계** | **13,276** | |

- 5년치는 약 80만 행, 연 약 16만 행이다.
- 한 달 전체 수집은 16개 구·군 × 7종 = 112회이고, 한 번에 1,000건을 넘는 구(기장군 아파트 전월세 1,048건)는 페이지가 추가되어 **113회 안팎**이다.
- **5년 백필 ≈ 6,800회, 매일 최근 3개월 재수집 ≈ 340회.**
- **일일 호출 한도는 확인하지 못했다.** 포털의 활용신청 정보에서 확인해야 하고, 한도에 따라 백필 일수가 정해진다(약 `6,800 / 한도`일).
