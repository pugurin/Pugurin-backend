# 시연 가이드 (서버 없이 프론트 + 백엔드 완성본)

운영 서버가 생기기 전에 **백엔드 담당 Mac을 임시 서버로 써서** 실제 앱으로 시연하는 방법이다.

```
[휴대폰 앱] ──HTTPS──▶ Cloudflare 임시 주소 ──▶ [백엔드 Mac: api · db · redis]
                     (https://xxxx.trycloudflare.com)        실데이터 약 14만 건
```

## 한눈에 보기

| 방법 | 앱 실행 위치 | 장점 | 단점 |
|---|---|---|---|
| **A. 임시 공개 주소 (추천)** | 실제 휴대폰 | 와이파이 상관없음, HTTPS라 앱 설정 변경이 거의 없음 | 실행할 때마다 주소가 바뀜. 인터넷이 꼭 필요 |
| B. 같은 네트워크 (핫스팟) | 실제 휴대폰 | 외부 서비스 없이 됨 | `http://`라서 앱에 예외 설정 필요. 학교 와이파이는 막힐 수 있음 |
| C. 한 대의 Mac에서 전부 | 시뮬레이터·에뮬레이터 | 네트워크 걱정이 가장 적음 | 실제 휴대폰이 아님 |

**추천 조합:** A로 시연하고, 인터넷이 안 되면 C로 넘어간다. 그것도 안 되면 미리 찍어 둔 영상을 튼다(맨 아래 "비상 대책").

---

## 공통 준비 (백엔드 Mac)

1. Docker Desktop을 켠다.
2. 레포 루트에서 서버를 띄운다.
   ```bash
   docker compose up -d
   docker compose ps                 # api·db·redis가 healthy
   ```
3. 데이터가 들어 있는지 확인한다.
   ```bash
   curl http://localhost:8000/api/v1/health      # {"status":"ok"}
   docker compose --profile worker run --rm worker python -m app.db status   # 거래 140,650건
   ```
   - 거래가 0건이면 `docker compose --profile worker run --rm worker python -m app.ingestion load`로 넣는다(2분쯤).
4. 시연 중에 Mac이 잠들지 않게 한다.
   - 전원 어댑터를 연결한다.
   - 시스템 설정 → 잠금 화면 → 화면 끄기와 자동 잠자기를 "안 함"으로 둔다. 또는 터미널에서 `caffeinate -d`를 켜 둔다.

## A. 임시 공개 주소로 시연 (추천)

Cloudflare의 무료 임시 터널을 쓴다. 가입이 필요 없고 HTTPS 주소가 바로 나온다.

**백엔드 Mac**
```bash
brew install cloudflared                       # 처음 한 번
cloudflared tunnel --url http://localhost:8000
```
출력에 나오는 `https://xxxx-xxxx.trycloudflare.com`이 이번 시연의 서버 주소다. **이 터미널 창을 끄면 주소가 사라진다.**

**확인 (아무 기기에서나)**
```
https://xxxx-xxxx.trycloudflare.com/api/v1/health   → {"status":"ok"}
```

**프론트 (앱)**
- API 주소를 `https://xxxx-xxxx.trycloudflare.com/api/v1`로 바꾼다.
- **주소가 실행할 때마다 바뀐다.** 그래서 앱이 서버 주소를 빌드 설정(.env 등)에서 읽게 해 두고, 시연 당일 터널을 켠 뒤 그 주소로 앱을 실행·빌드한다.
- HTTPS라서 Android `usesCleartextTraffic`, iOS ATS 예외 설정이 필요 없다.

**주의**
- 터널을 켠 동안 백엔드 Mac이 인터넷에 공개된다. **시연이 끝나면 바로 `Ctrl+C`로 끈다.**
  - 공개 API만 나가고, 내부 상태 확인 경로(`/internal/...`)는 밖에서 404다.
  - 요청 한도(기기당 분당 300회)도 그대로 적용된다.
- 임시 터널은 시연·테스트용이다. 느리거나 끊기면 터널을 다시 켜고 새 주소로 바꾼다.
- 고정 주소가 필요하면 Cloudflare 계정과 도메인으로 이름 있는 터널을 만들 수 있다. 하지만 그럴 거면 운영 서버([`DEPLOY.md`](./DEPLOY.md))를 쓰는 게 낫다.

## B. 같은 네트워크에서 시연 (핫스팟)

학교 와이파이는 기기끼리 통신을 막는 경우가 많다. **휴대폰 핫스팟에 Mac과 시연용 휴대폰을 같이 연결**하는 게 확실하다.

**백엔드 Mac:** IP를 확인한다.
```bash
ipconfig getifaddr en0          # 예: 172.20.10.2
```

**프론트 (앱)**
- API 주소를 `http://<위 IP>:8000/api/v1`로 바꾼다.
- `http://`라서 OS가 막는다. 개발 빌드에 아래 예외를 넣는다.
  - Android: `android:usesCleartextTraffic="true"` 또는 network security config에 그 IP 허용
  - iOS: Info.plist의 ATS 예외(`NSAllowsArbitraryLoads` 또는 해당 IP 예외)
- 핫스팟을 껐다 켜면 IP가 바뀔 수 있다. 시연 직전에 다시 확인한다.

## C. 한 대의 Mac에서 전부 (시뮬레이터)

네트워크가 전혀 안 될 때를 위한 방법이다. 프론트 앱을 백엔드 Mac에서 실행한다.

| 앱 실행 환경 | API 주소 |
|---|---|
| iOS 시뮬레이터, 웹 | `http://localhost:8000/api/v1` |
| Android 에뮬레이터 | `http://10.0.2.2:8000/api/v1` (Android는 cleartext 허용 필요) |

프론트 코드와 실행 환경(Xcode, Android Studio, Node 등)을 백엔드 Mac에 미리 준비해야 한다. 반대로 프론트 담당 노트북에서 백엔드를 띄우는 방법도 있다. 이때는 `.cache`를 전달하고 그 노트북에서 `load`를 실행한다(README "실데이터로 띄우는 방법").

## 시연 시나리오 (실데이터로 잘 보이는 것)

| 순서 | 화면 | 보여줄 것 |
|---|---|---|
| 1 | 지도 (부산 전체) | 구·군별 최근 12개월 평당가·거래 수 |
| 2 | 확대 → 해운대구·수영구 | 동 단위 → 단지 마커, 최근 거래가 |
| 3 | 단지 상세 | 평형별 거래 이력, 시세 추이 그래프 |
| 4 | 분석 | 이 단지 vs 같은 동 전체 추이 비교 |
| 5 | 검색 | "센텀", "해운대구 우동" 같은 단지·지역·주소 검색 |
| 6 | 전세·월세 | 거래 유형 전환. 갱신 계약은 기본으로 빠지고 옵션으로 포함 |
| 7 | 용어 해설 | 건폐율·용적률 등을 쉬운 말로 |

**피하거나 미리 설명할 것**
- **토지 상세(필지 정보):** 공급처가 없어 "토지 정보를 불러올 수 없어요"가 나온다(토지 거래 통계는 됨).
- **세대수·공급 평형("34평"):** 원천에 없어 비어 있다. 지금은 전용면적 기준이다.
- **1년보다 긴 기간:** 지금은 최근 12개월만 받아 둬서 그 이전은 비어 있다. 5년치 백필은 서버가 생기면 한다.
- **로그인·관심 단지·채팅:** 2차 기능이라 아직 없다.
- 데이터 기준일은 마지막 수집일(현재 2026-10-06)이다. 시연 전날 `python -m app.ingestion refresh`로 최신화할 수 있다(키 필요, 호출 약 340회).

## 시연 전 체크리스트

**하루 전 (리허설)**
- [ ] 백엔드 Mac에서 `docker compose up -d`, health OK, 거래 14만 건
- [ ] 터널 켜고 **실제 시연용 휴대폰**으로 앱 실행 → 지도·상세·검색까지 한 바퀴
- [ ] 프론트가 서버 주소를 설정에서 바꿀 수 있는지 확인(터널 주소가 매번 바뀜)
- [ ] 비상용 시연 영상 녹화

**당일**
- [ ] Mac 전원 연결, 잠자기 끄기
- [ ] `docker compose up -d` → health 확인
- [ ] 터널 켜기 → 새 주소를 프론트에 전달 → 앱에 반영
- [ ] 휴대폰으로 health 주소 열어 보기
- [ ] 시연 후 터널 끄기 (`Ctrl+C`)

## 비상 대책

| 상황 | 대응 |
|---|---|
| 터널 주소가 안 열림 | 터널을 껐다 켜서 새 주소 → 앱에 반영. 안 되면 B 또는 C |
| 앱이 서버에 못 붙음 | 휴대폰 브라우저로 `.../api/v1/health` 열어 보기. 열리면 앱 쪽 주소·헤더 문제 |
| 응답이 `400`이고 `X-Device-Id` 언급 | 앱이 모든 `/api/v1` 요청에 `X-Device-Id`(UUID) 헤더를 보내야 한다 |
| 지도가 비어 있음 | 백엔드 Mac에서 거래 건수 확인(공통 준비 3번) |
| 인터넷이 아예 없음 | C(시뮬레이터) 또는 녹화 영상 |
| 백엔드만 보여줘야 할 때 | 백엔드 Mac 브라우저에서 `http://localhost:8000/docs`(API 문서 화면)로 직접 호출 |
