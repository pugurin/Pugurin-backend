## 1. 서비스 개요

| 항목 | 내용 |
|---|---|
| 서비스 | 부산 지도 위에 실거래가를 단지 단위로 보여주고, 토지 정보를 쉬운 말로 설명하며, 소유자가 올린 매물을 보고 **소유자에게 직접 문의**한다 |
| 대상 지역 | 부산광역시 16개 구·군 |
| 매물 유형 | 아파트, 오피스텔, 연립·다세대(빌라), 토지 |
| 거래 유형 | 매매(중심), 전세, 월세 |
| 핵심 사용자 | 40~50대 실구매 수요자. 대부분 로그인 없이 조회 |
| 거래 흐름 | **거래 희망자 → 소유자** (중개사를 거치지 않음). 중개사 기능은 보류 |
| 범위 밖 | 가격 예측·투자 추천, 앱 안 계약·결제, 매물과 무관한 사용자 간 채팅, 중개 수수료·알선, 자체 광고 서버 |
| 서비스 목적 | **정보 전달 + 문의 창구**. 앱은 실거래·매물 정보와 소유자 문의 채팅까지만 제공하고, 계약·결제는 앱 밖에서 당사자끼리 한다 |
| 수익모델 | 광고(앱에서 외부 광고 SDK 연동). **사용자 유치가 최우선** |
| 참고 서비스 | 디스코(앱을 열면 바로 지도, 오래된 실거래는 불필요), 당근 부동산 |
| 플랫폼 | **앱(Expo / React Native) + 웹**. 백엔드 API는 하나로 같이 쓴다 |

## 2. 사용자 유형

| 유형 | 코드 | 설명 | 할 수 있는 일 |
|---|---|---|---|
| 비로그인 사용자 | `guest` | 앱·웹에서 로그인하지 않은 사용자 | 지도·검색·단지·토지·분석·용어·매물 조회 |
| 일반 사용자 | `buyer` | 카카오·네이버로 가입한 사용자 | guest 기능 + 관심 등록, 알림, 매물 문의 채팅, 신고. **소유 확인을 마치면 매물 등록·문의 응대**(소유자) |
| 중개사 (보류) | `agent` | 검증을 통과한 공인중개사 | 보류 — 거래 흐름 변경으로 당분간 제공하지 않음 |
| 관리자 | `admin` | 내부 운영자 | 신고 처리(소유 확인 해제 포함), 용어 관리 |
| 시스템 | `system` | 배치·자동 처리 | 실거래가 수집, 알림 발송, 만료 처리 |

> "소유자"는 별도 역할이 아니라 **소유 확인(F-LST-07)을 통과한 일반 사용자**다. 역할 코드 `buyer`의 이름 정리는 §7에서 정한다.

## 5. 기능 상세

### 5.1 데이터 수집

#### F-DATA-01 실거래가 정기 수집
- **설명:** 공공데이터포털 실거래가 7종(아파트·오피스텔·연립다세대 매매/전월세, 토지 매매)을 매일 1회 수집해 저장한다.
- **규칙**
  - 부산 16개 구·군만 수집한다.
  - 같은 거래를 여러 번 수집해도 **한 건만** 저장된다(중복 없음). 원천에 거래 고유 ID가 없으므로 **자연키 `source_key`** 로 판정한다([ERD §3.1](./ERD.md)).
    - 구성: 종류, 시군구, 법정동명, 지번, 건물명, 단지 식별자, 동, 층, 면적, 계약일, 금액 + **같은 응답 안 순번**(같은 날·같은 층·같은 금액 거래가 실제로 여러 건인 경우 구분).
    - 해제 여부·등기일·중개/직거래처럼 나중에 바뀌는 값은 키에 넣지 않는다.
    - 금액·면적 정정은 키가 바뀐다 → 재수집에서 사라진 이전 행은 **삭제 표시**한다([ERD §3.2](./ERD.md)).
  - 신고 기한(30일)과 정정 신고 때문에 **최근 3개월은 매일 다시 수집**한다.
  - **장기 재수집:** 해제·정정은 계약 후 몇 달 뒤(잔금 전)에도 신고되므로, **4~24개월 전 계약월은 주 1회** 다시 수집한다. 범위·주기는 API 일일 한도를 보고 정한다(§7). 24개월보다 오래된 계약의 해제·정정은 반영하지 못한다.
  - 금액은 원 단위로 저장한다(원천은 만원 단위).
  - 거래유형(중개거래/직거래)을 함께 저장한다.
  - 전월세는 월세가 0이면 **전세**로 본다.
  - 전월세는 계약 구분(신규/갱신)을 함께 저장한다. 아파트 전월세는 직전 보증금·갱신요구권 사용 여부도 저장한다.
  - 전월세 원천에는 해제 여부·중개/직거래 구분이 **없다**(조사 결과, #3).
- **예외**
  - 외부 API 일일 호출 한도 초과 → 남은 작업은 다음 실행으로 미룬다.
  - 외부 API 장애 → 실행 기록에 실패로 남기고, 기존 데이터는 그대로 서비스한다.
- **API / 이슈:** 내부 배치 / #6 #7

#### F-DATA-02 해제(취소) 거래 반영
- **설명:** 계약 후 해제 신고된 거래를 표시하고 통계에서 뺀다.
- **규칙**
  - 해제된 거래는 지도·통계·기본 목록에 **나오지 않는다**.
  - 거래 목록에서 `해제 거래 포함`을 켜면 "해제" 표시와 함께 보인다.
  - 해제는 별도 행이 아니라 **원래 거래에 해제 표시가 붙어서** 온다.
  - 전월세는 원천에 해제 정보가 없어 이 기능이 적용되지 않는다.
  - 계약 후 늦게 신고된 해제는 장기 재수집(F-DATA-01)으로 반영한다.
- **이유:** 일명 "집값 띄우기" 허위 신고 거래가 시세를 왜곡하지 않게 한다.
- **API / 이슈:** 내부 배치, `GET /transactions?include_cancelled=` / #7

#### F-DATA-03 위치 변환 및 단지 묶기
- **설명:** 거래의 지번 주소를 좌표로 바꾸고, 아파트·오피스텔·빌라 거래를 단지·건물 단위로 묶는다.
- **규칙**
  - 좌표는 서버가 카카오 로컬 지오코딩으로 계산한다.
  - 지번이 가려진 거래(토지 전부)는 **동네 중심점**에 두고, 동네 통계에만 반영한다.
  - 단지별 평형 목록을 만들고, 가능하면 공급면적 기준 평형도 계산한다.
  - **확인 결과(#3): 토지 거래는 지번이 100% 가려져 있다**(해운대구·기장군 표본). 토지는 법정동 단위로만 다룬다.
  - 단지 묶기: 아파트는 원천의 단지 식별자(`aptSeq`)로, 오피스텔·빌라는 (시군구, 법정동명, 지번, 건물명)으로 묶는다.
  - 법정동 코드는 아파트 매매만 원천에 있으므로 **법정동 코드 마스터**로 이름 → 코드를 매핑한다(기장군은 리 단위까지 옴).
- **예외:** 좌표 변환 실패 → 실패 목록에 남기고 다음 실행 때 다시 시도한다.
- **API / 이슈:** 내부 배치 / #8

#### F-DATA-04 데이터 기준일 안내
- **설명:** 실거래가를 보여주는 모든 화면에 "언제 기준 데이터인지"를 함께 제공한다.
- **규칙**

  - "최근 30일 거래는 아직 신고되지 않았을 수 있음" 안내 여부를 함께 준다.

### 5.2 지도

#### F-MAP-01 지도에서 실거래가 보기
- **설명:** 지도 화면에 보이는 영역의 실거래가를 마커로 보여준다. 앱을 켜면 가장 먼저 보이는 화면이다.
- **규칙**
  - 지도를 멀리서 보면 **구 단위**, 가까이 가면 **동 단위**, 더 가까이 가면 **단지·필지 단위**로 보여준다. 단계는 서버가 정한다.
  - 단지 마커에는 **최근 거래가, 평형, 계약일**을 표시한다.
    - 매매: 매매가 / 전세: 보증금 / 월세: "보증금/월세" (예: 5,000/80)
  - 구·동 마커에는 **거래 건수와 대표값(중위값)** 을 표시한다.
    - 매매: 평당 매매가 / 전세: 평당 보증금 / 월세: 보증금과 월세 각각 (보증금 조건이 제각각이라 평당 환산하지 않음)
  - 한 번에 최대 500개 마커. 넘으면 한 단계 넓은 단위로 묶는다.
  - 해제 거래는 제외한다.
  - 토지는 지번이 가려져 있어 **필지 마커가 거의 나오지 않는다.** 토지는 구·동 마커 중심으로 보여준다.
- **예외**
  - 지도 영역·줌 누락 → 입력 오류
  - 부산 밖 영역 → 빈 결과
- **API / 이슈:** `GET /map/markers` / #9

#### F-MAP-02 지도 필터
- **설명:** 지도에 보일 거래를 조건으로 거른다.
- **필터 항목**

| 항목 | 선택지 | 기본값 |
|---|---|---|
| 매물 유형 | 아파트 / 오피스텔 / 빌라 / 토지 중 **하나** | (필수) |
| 거래 유형 | 매매 / 전세 / 월세 | 매매 |
| 기간 | 최근 1~60개월 | 12개월 |
| 가격 | 매매가 / 보증금 / 월세 (거래 유형에 맞게) | 전체 |
| 면적 | 평 단위 범위 (**전용면적** 기준, 토지는 토지 면적) | 전체 |
| 직거래 제외 | 켜기/끄기 | 끄기 |

- **규칙**
  - 매물 유형은 **한 번에 하나만** 고른다(아파트와 토지 평당가를 섞으면 의미가 없음).
  - 토지는 **매매만** 선택할 수 있다.
  - 클라이언트 미팅에서 "오래된 실거래는 불필요"로 정해졌으므로 기간 상한(현재 60개월)은 재검토한다(§7).
- **API / 이슈:** `GET /map/markers` / #9

#### F-MAP-03 평 단위 표시
- **설명:** 모든 면적을 ㎡와 **평**으로 함께 제공한다.
- **규칙**
  - 1평 = 3.3058㎡, 평은 소수 첫째 자리까지 표시한다.
  - 가격은 **평당가** 기준으로 비교한다.
  - 아파트는 사람들이 흔히 말하는 "34평"(공급면적 기준)을 **지도 마커부터** 함께 제공한다. 공급 평형이 없으면 "전용 25.7평"처럼 전용임을 밝혀 표시한다.
  - 면적 필드 이름은 전용(`exclusive_`), 공급(`supply_`), 토지(`land_`)로 구분한다.
- **API / 이슈:** 전 응답 공통 / #9 #10

#### F-MAP-04 입지 특징 표시 (역세권 등)
- **설명:** 단지·필지에 "역세권" 같은 입지 특징을 표시한다(클라이언트 미팅 요청).
- **규칙**
  - 특징마다 **기준을 먼저 정의**한다. 예: 역세권 = 지하철역 출입구에서 도보 5~10분(기준 거리 미정).
  - 기준과 출처를 화면에 함께 보여준다.
- **상태:** 기준·데이터 출처 미정(§7). 단계 미정.

### 5.3 검색

#### F-SRCH-01 단지·주소·동네 통합 검색
- **설명:** 검색창 하나로 단지명("해운대아이파크"), 주소("우동 1407"), 동네("해운대구 우동")를 찾는다. 결과를 누르면 지도가 그 위치로 이동한다.
- **규칙**
  - 2글자 이상 입력해야 검색한다.
  - 최대 30개 결과. 단지 → 동네 → 주소 순으로 보여준다.
  - 부산 밖 결과는 제외한다.
- **결과를 눌렀을 때**
  - 동네·구: 그 지역 **경계 범위(bbox)** 에 맞춰 지도를 이동한다.
  - 단지: 단지 위치로 이동하고 단지 정보를 연다.
  - 주소: 그 위치로 지도를 이동한다. 토지 정보는 공급처가 생긴 뒤에만 연다(F-LAND-01 상태를 따름).

### 5.5 토지

#### F-LAND-01 지도 클릭으로 토지 정보 보기
- **설명:** 지도에서 땅을 누르면 그 필지의 정보를 보여준다.
- **상태:** VWorld를 쓰지 않기로 해서 토지이용계획·토지특성·필지 경계의 **공급처가 없다.** 정해지기 전까지는 항상 "토지 정보를 잠시 불러올 수 없어요"로 응답한다(§7).
- **제공 정보:** 지번 주소, 지목(대·전·답 등), 면적(㎡·평), 공시지가, 도로 접면, 모양, 용도지역, 규제 목록
- **규칙**
  - 누른 필지의 **경계선**을 함께 제공해 지도에서 하이라이트한다(앱에 별도 키 불필요).
  - 같은 필지는 30일 동안 저장해 둔 결과를 쓴다(외부 호출 절약).
- **정보가 없는 경우** — 오류가 아니라 정상 응답으로 처리하고, 이유에 맞는 안내를 보여준다.

| 상황 | 안내 문구 예시 |
|---|---|
| 도로·바다·하천 등 필지가 없는 곳 | "이곳은 토지 정보가 없어요" |
| 부산 밖 | "부산 지역만 지원해요" |
| 토지 정보 공급처 장애·미구성 + 저장된 결과 없음 | "토지 정보를 잠시 불러올 수 없어요" (지도는 계속 사용 가능) |

- **예외:** 좌표·필지번호 형식 자체가 잘못된 경우만 입력 오류.
- **API / 이슈:** `GET /parcels/lookup`, `GET /parcels/{pnu}` / #12

#### F-LAND-02 건폐율·용적률 한도 안내
- **설명:** 이 땅에 건물을 얼마나 넓고 높게 지을 수 있는지(건폐율·용적률 한도)를 보여준다.
- **규칙**
  - 한도는 **부산광역시 도시계획 조례**의 용도지역별 기준으로 계산하고, 출처를 함께 표시한다.
  - 한 필지가 **여러 용도지역에 걸치면** 전부 보여주고, 각각 필지에서 차지하는 비율(예: 제2종일반주거 80%, 일반상업 20%)을 함께 표시한다.
  - 토지 매매 실거래가에는 용도지역(`landUse`)이 있어 거래 단위로는 용도지역을 보여줄 수 있다.
- **API / 이슈:** `GET /parcels/{pnu}` 의 `zonings` / #12

#### F-LAND-03 토지 규제 쉬운 설명
- **설명:** "가축사육제한구역" 같은 규제 이름마다 한 문장 쉬운 설명을 붙인다.
- **예:** 가축사육제한구역 → "소·돼지 등 가축을 키우는 시설을 지을 수 없어요."
- **규칙:** 관련 용어 해설(F-GLOS)로 바로 이동할 수 있게 용어 ID를 함께 준다.
- **API / 이슈:** `GET /parcels/{pnu}` 의 `restrictions` / #12

### 5.6 분석

#### F-ANAL-01 단지 분석
- **설명:** 단지 시세 추이를 **같은 동네 전체 추이와 비교**하고, 단지가 속한 땅의 용도지역을 요약한다.
- **상태:** 용도지역 요약은 토지 정보 공급처(§7)에 의존한다. 공급처가 없으면 추이 비교만 제공한다.
- **API / 이슈:** `GET /analysis/complexes/{id}` / #13

#### F-ANAL-02 토지 분석
- **설명:** 필지 정보 + **같은 법정동 안 같은 지목** 토지의 평당가 추이 + 조례 기준으로 **지을 수 있는 최대 규모**(단순 계산)를 보여준다.
- **상태:** 필지 정보·최대 규모 계산은 토지 정보 공급처(§7)에 의존한다. 공급처가 없으면 동 단위 토지 거래 추이만 제공한다.
- **동 단위인 이유:** 토지 거래는 지번이 100% 가려져 동 중심점 좌표밖에 없으므로, "주변 500m" 같은 거리 기준 비교는 공급처가 생겨도 불가능하다.
- **예:** "대지 460평 기준 건축면적 최대 약 276평, 연면적 최대 약 1,150평"
- **규칙**
  - "오를 것이다", "사세요" 같은 **예측·권유 문구는 쓰지 않는다.**
  - "참고용이며 실제 건축 가능 여부는 관할 구청 확인 필요" 안내를 항상 붙인다.
  - 여러 용도지역에 걸친 필지는 면적 비율로 가중평균해 계산하고 "실제와 다를 수 있음"을 덧붙인다.
  - 토지 거래는 **지분거래·지목 '도로'** 비중이 높다(해운대·수영 1개월 45건 중 둘을 빼면 7건). 평당가 통계에서 제외할지 정한다(§7).
  - 평당가 옆에 **거래 건수(표본 수)** 를 함께 보여준다.
- **API / 이슈:** `GET /analysis/parcels/{pnu}` / #13

### 5.7 용어 해설

#### F-GLOS-01 용어 목록·검색
- **설명:** 부동산 용어(건폐율, 용적률, 공시지가, 전용면적 등)를 목록으로 보고 검색한다.
- **규칙**
  - 용어마다 **한 줄 설명**(말풍선용)과 **자세한 설명**(상세 화면용), 예시를 둔다.
  - 한 줄 설명은 40~50대가 한 번에 이해할 수 있는 말로 쓴다.
  - **분류 칩**으로 거를 수 있다: 거래 / 토지 / 건물 / 세금
  - **자주 찾는 용어**를 따로 모아 보여준다.
  - 정렬은 관리자가 정한 순서 → 가나다순.
- **API / 이슈:** `GET /glossary`, `GET /glossary/{term_id}` / #14

#### F-GLOS-02 화면 속 용어 설명 연결
- **설명:** 토지·단지 화면의 어려운 용어를 누르면 해당 용어 설명을 보여준다.
- **규칙:** 응답에 **"어떤 항목 → 어떤 용어"** 연결표를 넣어, 앱이 건폐율 옆에는 건폐율 설명을, 공시지가 옆에는 공시지가 설명을 정확히 붙이게 한다(별도 추천 기능 없음).
- **API / 이슈:** `glossary` 필드 / #14

### 5.7-1 AI (검토)

#### F-AI-01 AI 부동산 도우미
- **설명:** 용어·화면 내용을 쉬운 말로 풀어 주는 AI 기능. 클라이언트 미팅에서 "있으면 좋음"으로 언급됨.
- **규칙**
  - **가격 상승률 추천·예측은 하지 않는다**(클라이언트 결정).
  - "사세요", "오를 것이다" 같은 권유·예측 문구를 쓰지 않는다(F-ANAL-02와 같은 기준).
  - 답변에 근거 데이터(실거래·용어 해설)와 기준일을 함께 보여준다.
- **상태:** 범위·단계 미정(§7).

### 5.8 계정

#### F-AUTH-01 소셜 로그인·가입
- **설명:** 카카오 또는 네이버 계정으로 로그인한다. 처음이면 자동으로 가입된다.
- **규칙**
  - 이메일·비밀번호 가입은 제공하지 않는다.
  - 처음 가입할 때 **이용약관·개인정보 처리 동의**가 필수다.
  - 가입하면 일반 사용자(`buyer`)가 된다.
  - 웹은 리다이렉트 방식으로 로그인하고, 갱신 토큰은 자바스크립트가 읽을 수 없는 쿠키(HttpOnly·Secure)에 둔다.
- **예외:** 필수 동의 누락 → 입력 오류 / 소셜 인증 실패 → 인증 오류
- **API / 이슈:** `POST /auth/oauth/{provider}` / #16

#### F-AUTH-02 로그인 유지
- **설명:** 한 번 로그인하면 14일 동안 다시 로그인하지 않아도 된다.
- **규칙**
  - 접근 토큰은 30분, 갱신 토큰은 14일 유효하다.
  - 갱신할 때마다 새 갱신 토큰을 발급하고 이전 것은 폐기한다.
  - 폐기된 토큰이 다시 쓰이면(탈취 의심) 그 사용자의 **모든 기기를 로그아웃**시킨다.
- **API / 이슈:** `POST /auth/refresh` / #16

#### F-AUTH-03 로그아웃
- **설명:** 현재 기기에서 로그아웃하고, 이 기기로 가던 푸시 알림도 끊는다.
- **API / 이슈:** `POST /auth/logout` / #16

#### F-AUTH-04 내 정보 보기·수정
- **설명:** 닉네임, 역할, 소유 확인 상태, 내 매물 수, 알림 설정을 보고 닉네임을 바꾼다.
- **API / 이슈:** `GET /users/me`, `PATCH /users/me` / #16

#### F-AUTH-05 회원 탈퇴
- **설명:** 계정을 삭제한다.
- **규칙**
  - 개인정보는 **즉시 파기(익명화)** 하고, 법으로 보관해야 하는 것만 따로 보관한다.
  - 상대방 채팅 화면에는 "탈퇴한 사용자"로 표시된다.
  - 같은 소셜 계정으로 **다시 가입할 수 있다**(이전 기록과 연결하지 않음).
  - 매물을 올린 소유자가 탈퇴하면 그 매물은 즉시 숨기고, 진행 중인 문의 채팅방에는 "탈퇴한 사용자"로 표시한다.
- **API / 이슈:** `DELETE /users/me` / #16

### 5.9 중개사 (보류)

> **보류:** 거래 흐름이 `거래 희망자 → 소유자`로 바뀌어 중개사 기능은 당분간 제공하지 않는다. 아래 내용은 재개할 때 참고하도록 남겨 둔다.

#### F-AGT-01 중개사 승격 신청
- **설명:** 일반 사용자가 사무소 정보(상호, 대표자, 사업자등록번호, 중개사무소 등록번호, 주소, 전화)를 입력해 중개사 계정으로 바꿔 달라고 신청한다.
- **규칙**
  - 로그인한 일반 사용자만 신청할 수 있다.
  - 사무소 좌표는 서버가 주소로 계산한다.
  - 이미 심사 중인 신청이 있으면 다시 신청할 수 없다.
- **흐름:** 가입(buyer) → 로그인 → (필요 시 서류 업로드) → 신청 → 자동 검증(F-AGT-02) → 통과 시 즉시 승인 / 실패 시 관리자 심사(F-ADM-01)
- **API / 이슈:** `POST /agents/me/application`, `GET /agents/me/application` / #17

#### F-AGT-02 중개사 자동 검증
- **설명:** 신청 정보를 공공 API로 확인해 사람이 보지 않고도 승인한다.
- **규칙**
  - 국세청: 사업자가 **계속 영업 중**인지 확인
  - 중개업자 조회: **등록번호·상호·대표자** 일치 확인 — 공급처가 없어 현재는 관리자 수동 심사
  - 모두 통과 → 즉시 승인 / 하나라도 실패 → 심사 대기, 자격증 서류 필수
  - 중개업자 조회 공급처가 없으므로 **현재는 모든 신청이 관리자 수동 심사(F-ADM-01)로 간다.**
- **API / 이슈:** 내부 처리 / #17

#### F-AGT-03 주변 중개사 찾기
- **설명:** 지도 위치 기준 반경 안의 중개사무소를 보여준다.
- **규칙**
  - 반경 기본 1km, 최대 5km (미터 단위로 정확히 계산)
  - **승인된 중개사만** 보인다.
- **API / 이슈:** `GET /agents` / #17

#### F-AGT-04 중개사 프로필·전화 걸기
- **설명:** 사무소명, 대표자, 등록번호, 주소, 전화번호, 소개, 채팅 응답률·응답 시간을 보여준다. **전화 걸기** 버튼으로 바로 연결한다.
- **규칙:** 미승인 중개사는 "찾을 수 없음"으로 처리한다.
- **API / 이슈:** `GET /agents/{id}` / #17

#### F-AGT-05 중개사 프로필 수정
- **설명:** 승인된 중개사가 사무소 소개, 사진, 주로 다루는 지역을 수정한다.
- **API / 이슈:** `PATCH /agents/me/profile` / #17

### 5.10 파일

#### F-UPL-01 사진 업로드
- **설명:** 매물 사진, 프로필 사진을 올린다. 소유 확인은 서류를 받지 않고 외부 확인으로 한다(F-LST-07). (중개사 자격 서류는 보류)
- **규칙**

  - 이미지는 썸네일을 자동으로 만든다.
  - 올리고 24시간 안에 어디에도 쓰이지 않은 파일은 자동 삭제한다.
- **API / 이슈:** `POST /uploads`, `POST /uploads/{id}/complete`, `GET /uploads/{id}` / #18

### 5.11 관심

#### F-INT-01 관심 단지 등록
- **설명:** 단지를 관심 목록에 넣고, 새 거래가 생기면 알림을 받는다(F-NOTI-03).
- **규칙:** 여러 번 눌러도 한 번만 등록된다. 목록에는 단지별 최근 거래를 함께 보여준다.

### 5.12 채팅

#### F-CHAT-01 소유자에게 매물 문의 시작
- **설명:** 매물 화면에서 그 매물을 올린 소유자에게 채팅으로 문의한다.
- **규칙**
  - **매물이 있어야만** 시작할 수 있다. 채팅방은 항상 매물 하나에 묶인다.
  - **문의자 → 소유자** 방향으로만 시작할 수 있다(소유자가 먼저 말 걸기 불가, 스팸 방지).
  - 같은 사람이 같은 매물로 다시 문의하면 **기존 채팅방으로 이어진다.**
  - 자기 매물에는 문의할 수 없다.
  - 매물과 무관한 사용자끼리 채팅은 제공하지 않는다.
  - 소유자 전화번호는 기본으로 공개하지 않는다(공개 여부·안심번호는 §7).
- **예외:** 숨김·만료·삭제된 매물, 탈퇴한 소유자 → 찾을 수 없음 / 거래완료 매물 → 새 문의 불가(기존 방은 유지)
- **API / 이슈:** `POST /chat/rooms` / #20

#### F-CHAT-02 채팅방 목록
- **설명:** 내 채팅방을 최근 대화순으로 보여준다(상대 이름, **어떤 매물 문의인지**, 마지막 메시지, 안 읽은 수). 내가 문의한 방과 내 매물로 들어온 문의를 구분해 볼 수 있다.
- **API / 이슈:** `GET /chat/rooms`, `GET /chat/rooms/{id}` / #20

#### F-CHAT-03 실시간 메시지 주고받기
- **설명:** 메시지를 보내면 상대에게 바로 전달된다.
- **규칙**
  - 메시지는 1~1,000자
  - 앱이 실시간 연결을 잃어도 **일반 전송으로 보낼 수 있다.**
  - 같은 메시지를 재전송해도 **한 번만 저장**된다.
  - 1초에 5개까지만 보낼 수 있다.
  - 상대가 앱을 안 보고 있으면 푸시 알림이 간다(F-NOTI-04).
- **API / 이슈:** `WS /ws/chat`, `POST /chat/rooms/{id}/messages` / #20 #21

#### F-CHAT-04 이전 메시지 보기
- **설명:** 위로 스크롤하면 이전 메시지를 30개씩 더 불러온다.
- **API / 이슈:** `GET /chat/rooms/{id}/messages` / #20

#### F-CHAT-05 읽음 표시
- **설명:** 상대가 메시지를 읽으면 실시간으로 읽음 표시가 된다.
- **API / 이슈:** `POST /chat/rooms/{id}/read`, WS `read_receipt` / #20 #21

#### F-CHAT-06 채팅방 나가기
- **설명:** 채팅방을 내 목록에서 숨긴다.
- **API / 이슈:** `POST /chat/rooms/{id}/leave` / #20

#### F-CHAT-07 상대 차단
- **설명:** 원치 않는 상대를 차단한다. 소유자가 특정 문의자를 막거나, 문의자가 소유자를 막을 때 쓴다.
- **규칙**
  - 차단하면 그 사람과의 모든 채팅방에서 메시지를 주고받을 수 없고, 상대는 내 매물에 새로 문의할 수 없다.
  - 상대에게 차단 사실을 알리지 않는다("메시지를 보낼 수 없어요"로만 표시).
  - 차단 목록에서 언제든 해제할 수 있다. 차단과 신고(F-RPT-01)는 별개다.
- **API / 이슈:** (안) `PUT/DELETE/GET /users/me/blocks` / #20

#### F-CHAT-08 채팅 안전 안내
- **설명:** 직거래에서 흔한 사기 수법을 채팅 화면에서 경고한다.
- **규칙**
  - 채팅방 상단에 고정 안내: "계약 전 등기부등본을 직접 확인하세요", "계약금은 등기상 소유자 명의 계좌로만 보내세요".
  - 메시지에 **계좌번호 형식·외부 메신저 아이디·외부 링크**가 있으면 보낸 쪽과 받은 쪽 모두에게 주의 문구를 붙인다(메시지는 막지 않음). 감지 규칙은 §7.
  - 메시지는 **텍스트만** 보낼 수 있다. 사진 전송 허용 여부는 §7.
- **API / 이슈:** 메시지 응답의 `warnings` 필드(안) / #20

### 5.13 알림

#### F-NOTI-01 푸시 기기 등록
- **설명:** 로그인한 기기를 푸시 알림 대상으로 등록하고, 로그아웃하면 해제한다.
- **API / 이슈:** `PUT/DELETE /devices/{device_id}` / #22

#### F-NOTI-02 알림함
- **설명:** 받은 알림을 목록으로 보고, 하나씩 또는 전체 읽음 처리한다.
- **API / 이슈:** `GET /notifications`, `POST /notifications/read` / #22

#### F-NOTI-03 관심 단지·지역 새 거래 알림
- **설명:** 매일 수집이 끝나면 관심 단지·지역에 새로 올라온 거래를 **묶어서 한 번** 알려준다.
- **규칙:** 여기서 "새 거래"는 **새로 수집된 거래**다. 계약일이 최대 30일 전일 수 있으므로 알림에 계약일을 표시한다.

#### F-NOTI-04 채팅 알림
- **설명:** 상대가 앱을 보고 있지 않을 때 새 메시지를 푸시로 알린다.
- **규칙:** 채팅 알림 설정이 꺼져 있으면 보내지 않는다.
- **API / 이슈:** 내부 처리 / #21 #22

#### F-NOTI-05 중개사 심사 결과 알림
- **상태:** 보류
- **설명:** 중개사 신청이 승인·반려되면 알린다(반려 사유 포함).
- **API / 이슈:** 내부 처리 / #22

#### F-NOTI-06 알림 수신 설정·광고성 동의
- **설명:** 채팅 알림, 관심 알림, 광고성 알림, 야간 광고성 알림을 각각 켜고 끈다.
- **규칙 (정보통신망법)**
  - 광고성 알림은 **동의한 사람에게만** 보낸다.
  - 밤 9시~아침 8시 광고성 알림은 **따로 동의**를 받는다.
  - 동의·철회한 날짜를 기록하고, **2년마다 다시 동의**를 받는다.
  - 광고성 알림 제목에는 `(광고)`를 붙인다.
- **API / 이슈:** `PUT /users/me/consents` / #16 #22

#### F-NOTI-07 소유 확인 해제 알림
- **설명:** 소유권 변동(F-LST-08)이나 관리자 조치(F-ADM-05)로 소유 확인이 해제되고 매물이 숨겨지면 이유와 함께 알린다.
- **규칙:** 확인 성공·실패 결과는 확인 직후 화면에 바로 보여주므로 따로 알리지 않는다.
- **API / 이슈:** 내부 처리 / #22

### 5.14 신고

#### F-RPT-01 신고하기
- **설명:** 매물, 채팅방, 사용자를 신고한다.
- **신고 사유:** 허위 매물, **소유자 아님 의심**, 가격 오류, 스팸, 욕설·비방, 불법 중개(소유자를 가장한 중개 영업), 기타
- **규칙:** 같은 대상을 두 번 신고할 수 없다.
- **API / 이슈:** `POST /reports` / #23

#### F-RPT-02 내 신고 처리 현황
- **설명:** 내가 한 신고가 처리됐는지 확인한다.
- **API / 이슈:** `GET /reports/me` / #23

#### F-RPT-03 신고 기반 임시 비노출
- **설명:** 믿을 만한 신고가 쌓이면 관리자 처리 전이라도 대상을 잠시 숨긴다.
- **규칙**
  - 신고 **건수가 아니라 신고자 신뢰도**로 판단한다(경쟁 업체가 계정 여러 개로 신고하는 것 방지).
  - 신뢰도 요소: 가입 기간, 과거 신고가 인정된 비율, 같은 기기·IP에서 대량 가입했는지 여부
  - 임시로 숨기는 건 **허위 매물·소유자 아님 의심 신고**에만 적용한다(소유 확인이 서비스 신뢰의 근간이므로). 나머지는 관리자 확인 대기 목록의 우선순위만 올린다.
  - 점수 기준은 정책 결정 후 확정한다.
- **API / 이슈:** 내부 처리 / #23

#### F-RPT-04 제재 이의제기

### 5.16 매물 (2차, 소유자 등록)

#### F-LST-01 매물 등록
- **설명:** **소유 확인(F-LST-07)을 통과한 소유자**가 직접 매물을 등록한다.
- **필수 입력** (공인중개사법 제18조의2 표시·광고 명시사항을 소유자 매물에도 자체 기준으로 적용)

| 구분 | 항목 |
|---|---|
| 공통 | 소재지, 면적, 가격, 매물 종류, 거래 형태 |
| 건축물 | 총층수, 사용승인일, 방향(기준 포함), 방·욕실 수, 입주 가능일, 주차 대수, 관리비 |
| 토지 | 지목 |
| 등록자 (자동 표시) | "소유자 직접 등록" 표시, 닉네임, 소유 확인 완료 표시 |

- **규칙**
  - 필수 항목이 빠지면 등록할 수 없다.
  - 좌표는 서버가 주소로 계산한다.
  - 동·호수는 저장만 하고 **공개하지 않는다.**
  - 등록하면 바로 지도에 보인다.
  - 소유 확인을 받은 부동산만 등록할 수 있다(확인받은 주소와 매물 소재지가 같아야 함).
  - 같은 부동산·같은 거래 유형으로 이미 올라와 있는 매물이 있으면 다시 등록할 수 없다.
- **API / 이슈:** `POST /listings` / #24

#### F-LST-02 매물 수정·삭제
- **설명:** 본인이 등록한 매물을 고치거나 지운다.
- **예외:** 다른 사람의 매물 → 권한 없음
- **API / 이슈:** `PATCH/DELETE /listings/{id}` / #24

#### F-LST-03 매물 상태 변경
- **설명:** 판매중 / 예약중 / 거래완료로 바꾼다.
- **API / 이슈:** `PATCH /listings/{id}/status` / #24

#### F-LST-04 매물 자동 만료·연장
- **설명:** 오래 방치된 매물을 자동으로 숨긴다.
- **규칙:** 등록 후 **30일**이 지나면 자동으로 숨긴다. 소유자가 "아직 판매 중"을 확인(연장)하면 다시 30일 보인다.
- **이유:** 허위·방치 매물 방지
- **API / 이슈:** `POST /listings/{id}/renew`, 내부 배치 / #24

#### F-LST-05 매물 보기
- **설명:** 지도·목록에서 매물을 보고 상세 정보와 등록한 소유자(닉네임, 소유 확인 표시)를 확인한 뒤 **문의하기**(F-CHAT-01)로 연결한다.
- **목록 필터:** 매물 유형(하나), 거래 유형, 가격(매매가·보증금·월세), 면적(평), 지역(지도 영역 또는 법정동). 정렬은 최신 등록순(기본), 가격 낮은순·높은순.
- **지도 표시**
  - 지도에는 **실거래 레이어**와 **매물 레이어**를 따로 두고, 위쪽 토글로 켜고 끈다(기본: 실거래만, 매물이 있는 지역이면 둘 다).
  - 매물 마커는 실거래 마커와 모양·색을 구분하고 **호가**를 표시한다. 줌 단계별 묶음 규칙은 F-MAP-01과 같다.
- **호가 vs 실거래 비교:** 매물 상세에 **같은 단지·같은 평형의 최근 실거래(최근 12개월 중위값과 건수)** 를 함께 보여준다. 토지는 같은 법정동·같은 지목 기준. "싸다/비싸다" 같은 평가 문구는 쓰지 않고 숫자만 보여준다.
- **규칙:** 조회수는 같은 기기에서 24시간 내 여러 번 봐도 1번으로 센다.
- **API / 이슈:** `GET /listings`, `GET /listings/{id}`, `GET /map/markers?layer=listings`(안) / #24

#### F-LST-06 매물 찜·거래완료 알림
- **설명:** 매물을 찜하고, 찜한 매물이 거래완료되면 알림을 받는다.
- **API / 이슈:** `/interests/listings` / #24

#### F-LST-07 소유 확인 (외부 본인인증 + 등기 대조)
- **설명:** 매물을 올리기 전에 그 부동산의 소유자인지 확인한다. 확인은 **외부 서비스**로 하고, 우리 서비스에는 **결과(참/거짓)만 남긴다.** 서류 업로드와 관리자 심사는 없다.
- **흐름**
  1. 로그인한 사용자가 매물 소재지를 입력한다(주소 검색, 동·호수 포함).
  2. 개인정보 처리 동의를 받는다(본인인증사·등기 조회 대행사에 처리 위탁, 결과만 보관).
  3. **외부 본인인증 화면으로 이동**한다(휴대폰 본인인증). 앱은 인앱 브라우저, 웹은 새 창·리다이렉트.
  4. 인증이 끝나면 서버가 인증사로부터 **실명·생년월일**을 받는다.
  5. 서버가 **등기 조회 대행 API**로 그 부동산 등기부의 **현재 소유자**(이름, 생년월일 앞 6자리)를 조회한다.
  6. 서버가 둘을 대조해 **참/거짓**을 정한다.
  7. 실명·생년월일·등기 내용은 **대조 직후 즉시 폐기**한다(DB·로그 어디에도 남기지 않음).
  8. 결과를 화면에 바로 보여준다. 참이면 매물 등록(F-LST-01)으로 이어진다.
- **저장하는 것 (결과 기록)**

| 항목 | 예시 | 용도 |
|---|---|---|
| 사용자 ID | 1024 | 누가 확인받았는지 |
| 부동산 식별값 | 등기 고유번호, 소재지(동·호수 포함) | 어떤 부동산인지, 매물 소재지와 일치 확인 |
| 결과 | 참 / 거짓 | 매물 등록 가능 여부 |
| 확인 시각 | 2026-10-07 14:00 | 기록 |
| 소유권 최종 변동 기준값 | 갑구 마지막 소유권 등기의 접수번호 | 소유권 변동 감지(F-LST-08) |
| 사용한 외부 업체 | 본인인증사·등기 조회 대행사 이름 | 장애·분쟁 대응 |

- **결과 기록도 개인정보다:** 실명은 남기지 않지만 "사용자 ID + 동·호수 포함 소재지 + 참" 조합은 "이 사람이 이 집 소유자"라는 재산 정보다. 그래서 다음을 지킨다.
  - 결과 기록은 본인과 관리자만 볼 수 있고, 매물 화면에는 "소유 확인 완료" 표시만 나간다.
  - 탈퇴하면 즉시 파기하고, 관련 매물이 모두 내려간 뒤에는 정해진 기간 후 파기한다(기간은 §7 법률 검토).

- **대조 규칙**
  - 등기부 현재 소유자의 **이름과 생년월일**이 본인인증 결과와 모두 같으면 참.
  - **공동소유**: 등록자가 공유자 중 한 명이면 참으로 보고 매물에 "공동소유" 표시를 붙인다. 다른 공유자 동의 없이 올릴 수 있어 분쟁 소지가 있으므로 허용 여부·동의 절차는 §7에서 정한다.
  - **법인 소유·신탁 등기**처럼 개인 소유자가 등기에 없으면 자동 확인이 불가능하다 → "자동 확인이 안 되는 부동산이에요" 안내, 등록 불가(§7).
- **규칙**
  - 부동산마다 따로 확인받는다. 확인 결과는 그 부동산에만 쓴다.
  - 본인인증과 등기 조회는 건당 비용이 들므로 **사용자당 하루 3회**까지 시도할 수 있다(실패 포함). 실명·식별정보를 남기지 않으므로 계정을 여러 개 만들면 이 제한과 정지 제재를 우회할 수 있다 → 본인인증 연계정보(CI) 해시 보관 여부는 §7.
  - 같은 부동산이 이미 다른 사용자 명의로 확인되어 있어도 시도는 막지 않는다(공동소유 가능). 매물 중복은 F-LST-01 규칙으로 막는다.
- **예외**
  - 본인인증 취소·실패 → 결과를 남기지 않고 처음 화면으로 돌아간다.
  - 등기에 없는 주소, 소재지 특정 불가(동·호수 누락 등) → 입력 오류.
  - 외부 업체 장애 → "잠시 후 다시 시도해 주세요". 이 경우 하루 시도 횟수에서 빼 준다.
- **이유:** 중개사를 거치지 않으므로 허위 매물과 소유자를 가장한 무등록 중개를 막을 장치가 필요하다. 서류를 받아 보관하지 않아 개인정보 부담과 심사 인력이 줄어든다(당근 부동산 집주인 인증과 같은 방식).
- **API / 이슈:** (안) `POST /ownership-verifications`(시작, 본인인증 URL 발급), `POST /ownership-verifications/{id}/complete`(인증 결과 수신·대조), `GET /users/me/ownerships` / #24

#### F-LST-08 소유 확인 유지 (소유권 변동 감지)
- **설명:** 확인 뒤 부동산이 팔리는 등 소유권이 바뀌면 확인을 해제한다.
- **규칙**
  - **매물 연장(F-LST-04) 때 한 번만** 등기를 다시 조회한다. 매물은 30일마다 연장해야 보이므로, 게시 중인 매물은 최대 30일 간격으로 재조회된다(별도 주기 배치를 두지 않아 비용이 두 번 나가지 않음).
  - 재조회가 외부 장애로 실패하면 연장은 해 주고 다음 날 다시 조회한다.
  - 재조회는 개인정보 없이 **소유권 최종 변동 기준값**만 비교한다. 값이 바뀌었으면 확인을 해제하고 매물을 숨긴 뒤 알린다(F-NOTI-07).
  - 해제된 사용자가 여전히 소유자라면(예: 공유자 추가) F-LST-07을 다시 하면 된다.
- **API / 이슈:** 내부 배치 / #24

#### F-LST-09 직거래 안전 안내
- **설명:** 중개사가 없으면 확인설명서·공제보험 같은 보호 장치도 없다. 특히 전세·월세 직거래는 전세사기·깡통전세에 취약하므로 매물 화면에 확인 안내를 **항상** 붙인다.
- **규칙**
  - 모든 매물: "계약 전 등기부등본을 직접 발급해 소유자·근저당·압류를 확인하세요" 안내와 **계약 전 체크리스트**(등기부 확인, 신분증 대조, 소유자 명의 계좌, 전입신고·확정일자)를 보여준다.
  - 전세 매물: 같은 단지·평형(빌라는 같은 동네·유형)의 최근 매매 실거래 중위값으로 **참고 전세가율**(보증금 ÷ 매매가)을 계산해 보여준다. 표본이 부족하면 "비교할 매매 거래가 부족해요"로 표시한다. 높고 낮음을 평가하는 문구는 쓰지 않는다.
  - 서비스는 소유 확인 때 등기 내용을 버리므로 근저당·압류를 대신 확인해 주지 않는다. 이 사실을 안내 문구에 밝힌다.
  - 전세 직거래 매물 자체를 막을지는 §7에서 정한다.
- **API / 이슈:** 매물 상세 응답의 `safety` 필드(안) / #24

- **설명:** 앱과 같은 API를 웹에서도 쓸 수 있게 한다.
- **규칙**
  - 허용한 웹 도메인에서만 브라우저 요청을 받는다(CORS).
  - 웹은 기기 ID가 없으므로 비로그인 요청 수 제한(F-SYS-01)은 브라우저별 임시 식별자로 센다.
  - 웹 로그인은 2차 기능이라 F-AUTH-01에 적는다.
  - 웹 푸시는 범위 밖. 웹 사용자는 알림함(F-NOTI-02)으로 확인한다(도입 여부는 §7).
- **API / 이슈:** 전 API 공통 / -

### 6.1 성공 지표 (안)

"사용자 유치 최우선"을 판단할 기준이다. 이벤트 수집은 광고 SDK와 같은 동의 정책(§6 법령)을 따른다.

| 지표 | 정의 | 왜 보나 |
|---|---|---|
| DAU / MAU | 하루·한 달 동안 앱·웹을 연 사용자 수 | 유치 규모 |
| 재방문율 | 첫 방문 후 7일·30일 안에 다시 연 비율 | 계속 쓸 만한지 |

| 용어 해설 열람률 | 상세 화면 세션 중 용어 설명을 연 비율 | "쉬운 설명" 차별점 검증 |
| 매물 등록 수·문의 전환율 (2차) | 소유 확인 완료 수, 매물 조회 중 문의 시작 비율 | 직거래 모델이 돌아가는지 |
