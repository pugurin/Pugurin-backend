# 관심 지역 주간 리포트 설계 (F-INT-02 · F-NOTI-02 · F-NOTI-03 확장)

- **상태:** 설계 합의(2026-11-23). 코드 없음.
- **관련 이슈:** 백엔드 #19(관심 지역) · #22(알림), 프론트 #140(관심 지역)
- **선행 PR:** 백엔드 #67(관심 목록을 회원 계정에 묶기, `user_interests` 0015) 위에 쌓는다.

## 1. 왜

이사 갈 **동네를 고르는 사람**이 후보 동네(법정동)를 관심 지역으로 등록해 두면, 앱을 일부러 열지 않아도 그 동네 소식을 **일주일에 한 번 "이번 주 정리"로** 받아 본다. 후보 동네의 변화를 꾸준히 따라가며 고르는 걸 돕는다.

## 2. 목표 · 하지 않는 것 · 실패 기준

**목표**

- 로그인한 회원이 법정동을 관심 지역으로 등록한다(최대 10개).
- 매주 월요일 아침, 지난주(월~일) 관심 지역 소식을 묶은 리포트 한 통을 **앱 안 알림함**에 넣는다.
- 알림함에서 리포트를 열어 동네별 내용을 보고, "지도에서 보기"로 그 동네로 간다.

**하지 않는 것(이번 범위 밖)**

- 앱·웹 푸시, 이메일 발송. 알림 본문(`title`, `summary`)은 나중에 푸시로 그대로 보낼 수 있게 만들어 둔다.
- 매일 알림, 관심 단지 새 거래 알림(F-NOTI-03의 단지 쪽).
- 전세·월세 흐름, 학교·편의시설 같은 생활 정보(매주 잘 바뀌지 않는다). 생활 편의 점수는 따로 다룬다.
- 아파트 외 유형(오피스텔·빌라·토지)의 거래 요약.

**이렇게 되면 실패다**

- 이미 보낸 지난주 리포트의 숫자가 나중에 바뀐다(늦게 신고된 거래가 들어와도 그대로여야 한다).
- cron이 두 번 돌거나 다시 돌려서 같은 주 리포트가 두 통 쌓인다.
- 탈퇴한 회원에게 리포트가 쌓이거나, 탈퇴 뒤 알림이 남는다.
- "오를 것", "추천", "지금이 기회" 같은 투자 권유성 문구가 들어간다(AGENTS.md §1). 사실만 쓴다.

## 3. 사용자가 보는 것

알림함 목록의 한 줄:

```
📍 관심 지역 주간 리포트 · 11/17~11/23
대연동 거래 12건 · 새 경매 2건 외 2개 동네
```

리포트를 열면 동네마다 한 덩어리(관심 지역 등록 순서가 아니라 이름순):

```
📍 대연동 · 11/17~11/23 정리
• 아파트 매매 12건 새로 신고 · 평당 중위 2,150만 (지난주보다 +1.2%)
• 이번 주 가장 비싼 거래: 대연힐스테이트 34평형 9.8억 (계약 11/02)
• 새 경매 2건 · 최저가 4.1억부터
• 재개발: 대연8구역이 '관리처분인가'로 단계가 바뀌었어요
[지도에서 대연동 보기]
```

그 주에 아무 소식이 없는 동네는 `📍 OO동 · 이번 주 새 소식이 없어요` 한 줄.
리포트 아래에 출처(국토교통부 실거래가 공개시스템, 대법원 법원경매정보·온비드, 부산광역시 정비사업 정보)와 "최근 30일 거래는 아직 신고되지 않았을 수 있어요"를 둔다.

## 4. 데이터 정의 (서버가 계산)

**주 단위 기간:** KST 월요일 00:00 ~ 다음 월요일 00:00(반열린 구간). 리포트는 그 다음 월요일 08:00에 만든다.

| 항목                    | 정의                                                                                                                                                                                                                                                                    |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 새로 신고된 아파트 매매 | `transactions`에서 `property_type='apartment'`, `deal_type='sale'`, `is_cancelled=false`, `deleted_at IS NULL`, `region_code`=그 법정동, 그리고 **처음 수집된 실행**(`first_seen_run_id`)이 `job='collect'`이고 `status`가 `success`·`partial`이며 그 실행의 `finished_at`이 그 주 안. 계약일 기준이 아니다(신고까지 최대 30일). 다만 **계약일이 리포트 주 시작보다 60일 넘게 이전인 거래는 뺀다**(백필·재적재가 옛 거래를 '새 거래'로 부풀리지 않게). |
| 평당 중위               | 위 거래의 평당가 중위값. 평당가 계산은 지도 마커와 같다(`market.py`의 `_PYEONG`, 전용면적 기준). 만 원 단위 반올림.                                                                                                                                                     |
| 지난주 대비             | 지난주 같은 정의로 구한 평당 중위와 비교한 변화율(소수 1자리). **이번 주·지난주 중 하나라도 3건 미만이면 비교를 빼고** 평당 중위만 쓴다(건수가 적으면 숫자가 튄다).                                                                                                     |
| 가장 비싼 거래          | 위 거래 중 가격 최고 1건: 단지명, 평형 표기(프론트 면적 표기와 같은 "N평형" — 공급평형을 알면 공급평형, 모르면 전용평), 가격, 계약일.                                                                                                                                   |
| 새 경매                 | `auctions`에서 `region_code`=그 법정동, `first_seen_at`이 그 주 안. 건수와 그중 최저 `min_price`. 그 주 안에 닫힌 것도 센다.                                                                                                                                            |
| 재개발 단계 변화 | `redevelopments`에서 단계가 그 주 안에 바뀐 구역(아래 §5.2) 중 `region_code`=그 법정동. "OO구역이 '단계 이름'으로 단계가 바뀌었어요". 법정동을 모르는 구역(지번 좌표가 없는 구역)은 넣지 않는다. |

숫자 표기(억·만, 평형)는 앱의 기존 표기 함수와 맞춘다. 서버는 원값(원, ㎡, 코드)과 함께 **표시용 문장**도 만들어 저장한다(푸시 본문에 그대로 쓰기 위해).

## 5. 저장

### 5.1 관심 지역 — `user_interests` 확장 (마이그레이션 0016)

- `kind` CHECK에 `'region'`을 더한다. `target_id`는 법정동 10자리 코드(`regions.level='dong'`).
- 종류별 한도: 단지·경매 200, **지역 10**. 넘으면 `409 CONFLICT`.
- 없는 코드·시군구 코드는 `404`.

### 5.2 재개발 단계 변화 기록 — `redevelopments`에 컬럼 추가 (같은 0016)

- `previous_stage text`, `stage_changed_at timestamptz`, `region_code varchar(10)`.
- `region_code`는 정비사업 동기화가 지번을 지오코딩할 때 받는 법정동 코드(`GeoResult.b_code`)다. 지번까지 맞은(`location_precise`) 구역만 채운다. 법정동 경계(`regions.boundary`)는 비어 있어 쓰지 않는다.
- 정비사업 동기화(`ingestion/redevelopment.py`)가 기존 구역의 `stage`가 달라졌을 때만 두 값을 채운다. 새로 생긴 구역은 비워 둔다(처음 본 구역을 "단계가 바뀌었다"고 하지 않는다).

### 5.3 알림 — `notifications` (같은 0016)

| 컬럼                         | 설명                                                                               |
| ---------------------------- | ---------------------------------------------------------------------------------- |
| `id uuid` PK                 |                                                                                    |
| `user_id uuid`               | `users.id` ON DELETE CASCADE. 탈퇴 트랜잭션에서 직접 지운다(관심 목록과 같은 이유) |
| `kind text`                  | `'region_report'` (CHECK, 나중에 종류를 늘린다)                                    |
| `period_start date`          | 리포트 주의 월요일                                                                 |
| `title text`, `summary text` | 목록·푸시용 한 줄씩                                                                |
| `payload jsonb`              | 동네별 내용(§4의 원값 + 표시 문장, 출처). 동 이름·시군구 이름·대표점 좌표도 **보낼 때 값으로 저장**한다(나중에 지역 정보가 바뀌어도 리포트는 그대로) |
| `created_at`, `read_at`      |                                                                                    |

- **UNIQUE (`user_id`, `kind`, `period_start`)**: 같은 주를 다시 돌려도 한 통(`ON CONFLICT DO NOTHING`). 이미 만든 리포트는 다시 계산해 덮지 않는다.
- 보관: 90일이 지난 알림은 리포트 배치가 돌 때 지운다. 관심 지역을 해제해도 이미 받은 리포트는 남긴다.

## 6. API

| Method | Path                               | 설명                                                    |
| ------ | ---------------------------------- | ------------------------------------------------------- |
| PUT    | `/interests/regions/{region_code}` | 관심 지역 등록(멱등)                                    |
| DELETE | `/interests/regions/{region_code}` | 해제(멱등, 204)                                         |
| GET    | `/interests/regions`               | 목록(동 이름·시군구 이름·대표점 포함, 최근 등록 순)     |
| GET    | `/interests`                       | 기존 응답에 `regions: [코드…]`를 더한다(별 표시용)      |
| GET    | `/notifications`                   | 알림함(최신순, `page`/`page_size`). `meta.unread_count` |
| GET    | `/notifications/{id}`              | 한 통(payload 포함)                                     |
| POST   | `/notifications/read`              | `{ "ids": [...] }` 또는 `{ "all": true }`로 읽음        |

- 모두 access token 필요(없거나 틀리면 401). 응답은 `Cache-Control: private, no-cache`.
- 남의 알림 id는 404.

## 7. 배치

- CLI: `python -m app.ingestion region-reports [--week YYYY-MM-DD]` (기본: 지난주).
- 자동 실행은 호스트 cron이 아니라 기존 `worker` 컨테이너(`app/ingestion/worker.py`)에 **주간 job**을 더한다: 매주 월요일 08:00 KST. 매일 04:00 수집이 끝난 뒤라 그 주 마지막 수집까지 들어간다. DEPLOY.md의 worker 설명에 한 줄 더한다.
- 관심 지역이 1개 이상인 탈퇴하지 않은 회원마다 리포트 한 통.
- **모든 관심 지역에 새 소식이 없으면 그 주는 보내지 않는다**(내 판단: 빈 알림이 쌓이면 알림함을 안 보게 된다).
- 실거래 수집(`job='collect'`, `success`·`partial`)이 그 주에 한 번도 끝나지 않았으면 리포트를 만들지 않고 경고 로그를 남긴다(빈 리포트를 "새 소식 없음"으로 잘못 보내지 않게).
- 결과(대상 회원 수, 만든 수, 건너뛴 수)를 출력한다.

## 8. 프론트 (웹)

- **관심 지역 등록:** 지역 시트(`MarketSheets.tsx`의 `RegionContent`)에 ☆. **동 단위(`level==='dong'`)일 때만** 보이고 구 단위에는 없다. 별 상태·낙관적 갱신·409 토스트는 기존 관심 훅(`src/state/interests.tsx`)에 `region` 종류를 더해 그대로 쓴다. 로그인 안 했으면 기존 로그인 안내 창(#165). 11번째 등록은 서버 409 문구를 토스트.
- **관심 목록 화면:** 단지 | 경매 | **지역** 탭. 지역을 누르면 지도를 그 동네로 옮긴다.
- **알림함:** 더보기에 "알림" 줄과 안 읽은 개수 배지. 목록 → 리포트 화면(§3). 열면 읽음 처리. "지도에서 OO동 보기"는 지도를 그 동네 대표점으로 옮긴다.
- 안 읽은 개수는 앱을 켤 때와 앱으로 돌아올 때(`AppState` active) `GET /notifications`로 받는다.

## 9. 개인정보

- 새로 저장하는 것: 관심 지역(법정동 코드), 알림(리포트 내용, 읽은 시각). 둘 다 탈퇴 시 즉시 삭제.
- 개인정보처리방침(프론트 `public/privacy.html`, #166)의 "서비스 이용 중 생성" 항목에 관심 지역·알림을, 보유 기간에 "알림 90일"을 더한다.

## 10. 방법 비교 (정한 것)

- **A. 매주 서버가 리포트를 만들어 저장 — 고름.** 보낸 리포트가 바뀌지 않고, 푸시를 붙일 때 저장된 알림을 그대로 보내면 된다. 명세의 알림함(F-NOTI-02)과 같은 구조.
- B. 알림함에는 항목만 두고 열 때 계산 — 다시 열면 숫자가 바뀔 수 있고, 푸시 본문을 만들 때 결국 미리 계산해야 해서 뺐다.
- C. 프론트에서 계산 — 백엔드 로직을 프론트에서 다시 만들지 않는다는 규칙에 어긋나 뺐다.

## 11. 설계하며 내가 정한 것 (확인 필요)

- 주기는 매주 월요일 08:00, 지난주 월~일.
- 아파트 매매만 요약한다(예시 문장 그대로).
- 지난주 대비는 양쪽 다 3건 이상일 때만.
- 모든 관심 지역이 무소식이면 그 주는 보내지 않는다.
- '새 거래'는 정기 수집(`collect`)이 처음 본 거래 중 계약일 60일 이내(백필로 부풀지 않게).
- 재개발은 지번 좌표가 있는 구역만(법정동 경계 데이터가 없어서).
- 알림 90일 보관, 관심 지역을 해제해도 받은 리포트는 남김.

## 12. 만드는 사람에게 맡기는 것

- `payload` JSON의 세부 필드 이름(§4의 내용은 모두 담을 것).
- 리포트 계산 SQL을 동네별로 나눌지 한 번에 할지.
- 알림함 화면의 세부 배치(§3의 문장과 순서는 지킨다).

## 13. 테스트

- 관심 지역: 등록 멱등·한도 10·없는 코드 404·시군구 코드 404·로그인 401·탈퇴 시 삭제.
- 리포트 계산(실제 PostGIS, 가짜 데이터): 주 경계(월 00:00 KST 안팎), 처음 수집 기준(계약일이 옛날이어도 이번 주 수집이면 포함), 해제 거래 제외, 지난주 비교 3건 미만이면 생략, 가장 비싼 거래, 새 경매, 재개발 단계 변화(새 구역은 제외), 모든 동네 무소식이면 안 보냄, 같은 주 두 번 돌려도 한 통, 수집이 없던 주는 만들지 않음.
- 알림 API: 최신순·안 읽은 개수·읽음 처리(ids·all)·남의 알림 404.
- 프론트: 지역 ☆, 지역 탭, 알림함 배지·읽음, 리포트 화면 문장.
