# 정비구역 경계 설계

재개발 레이어를 마커만이 아니라 **구역(면)**으로 보여 준다. 학구도처럼 공식 경계 파일을 받아 PostGIS에 싣고, 우리 정비사업 구역(`redevelopments`, 부산시 정비사업 정보)과 잇는다.

## 왜

- 부산시 정비사업 원천은 위치를 지번 한 점(또는 조합 사무실 주소)으로만 준다. 353개 중 좌표가 있는 구역은 66개라 지도에 마커가 66개뿐이었다.
- 사용자는 재개발 구역을 학구도처럼 **경계로** 보길 원한다(색은 다르게, 빗금으로 구분).

## 데이터

- **원천:** 브이월드 공간정보 다운로드 › 용도지역지구정보의 전국 **전체데이터** SHP(로그인 필요). 종류(`layer`)별 폴더에 둔다(git 제외, `data/redevelopment/`).
  | layer | 브이월드 이름 | 파일(2026-11-09) | 폴더 |
  |---|---|---|---|
  | `zone` | 도시및주거환경정비/정비구역 | `AL_D029_00_…` | `zones/` (필수) |
  | `promotion` | 도시재정비/재정비촉진지구 | `AL_D314_00_…` | `promotion/` |
  | `planned` | 정비예정구역/정비계획을수립중인지역 | `AL_D316_00_…` | `planned/` |
- 좌표계 EPSG:5186, DBF는 EUC-KR(cp949).
- **DBF 칸:** `A1` 도형 ID, `A3` 기준일, `A4` 시군구 코드(부산은 26으로 시작), `A5` 용도지역지구 코드(UDT100), `A7` 고시일, `A8` 비고, `A9` 이름(비거나 고시문만 있는 경우가 많다).
- 화면 출처 표시: "브이월드 용도지역지구정보".

## 싣는 규칙

2026-11-09 기준 파일(정비구역 + 재정비촉진)로 돌린 결과: 정비구역 250개, 재정비촉진 구역 14개를 실었다. 우리 구역 353개(그중 지번 좌표 있는 것 66개)와 106개가 이어졌고(좌표 35, 이름 71), 좌표가 없던 71개가 경계 대표점으로 위치를 얻었다. 조합 사무실로 잇기와 행정동 지번 보정은 서버 동기화(카카오 지오코딩) 뒤에 더해진다.

1. 부산(`A4`가 26으로 시작)만.
2. **부속 시설 제외:** `A8`·`A9`에 통로·도로·기반시설·공원·녹지·주차·광장·학교·용지·하수도·구거가 들어가면 구역이 아니라 구역 안의 시설이라 뺀다. 원천은 빈 칸을 NUL(`\x00`)로 채우므로 먼저 지운다.
3. **1,000㎡ 미만 조각 제외.** 실제 구역은 하위 10%도 약 8,000㎡다.
4. **다른 구역 안에 통째로 든 조각 제외.** 1m 여유를 둔다.
5. 이름: `A9`, 없으면 `A8`(비고)에서 찾는다. 비었거나 "고시"·"별도문의"만 있거나 사업 종류("주택재개발정비구역")만 있으면 이름이 아니다. 줄바꿈 뒤 정정 메모는 뗀다. "…고시 제…호"는 `notice`로 따로 둔다.
6. **재정비촉진(`promotion`):** 이름에 "촉진"과 "구역"이 있는 것만 싣는다. 지구 바깥 경계("…재정비촉진지구"), 존치 구역, 지구 안 시설 필지(근생·종교·교육·공공청사)는 뺀다. 이름 뒤 법 조문 설명("-국토의계획…")은 뗀다.
7. 한 트랜잭션에서 지우고 다시 넣는다(학구도와 같음).

## 우리 구역과 잇기 (일대일)

정비법 구역(`redevelopment`, `reconstruction`, `residential_improvement`, `urban_environment`)만 잇는다. 가로주택·소규모재건축은 법이 달라 이 파일에 경계가 없다.

1. **좌표:** 우리 구역의 지번 좌표(`location_precise`)를 품은 경계. 여럿이면 가장 큰 것.
2. **이름:** 핵심 이름이 같은 것. 핵심 이름은 공백·문장부호와 "주택/재개발/재건축/도시환경정비/주거환경개선/재정비촉진/정비/구역/사업/일원/지구" 같은 말을 뺀 것이다(예: "광안2주택재건축구역" → "광안2", "서,금사 재정비촉진(A)구역" → "서금사A"). 양쪽에서 그 핵심 이름이 하나뿐일 때만 잇는다.
3. **조합 사무실:** 위치가 사무실 주소인 구역은 그 주소를 따로 지오코딩해 둔다(`redevelopments.office_geom`, 지도 위치로는 쓰지 않음). 사무실이 아직 안 이어진 경계 안에 있고, 그 경계에 다른 조합 사무실이 없고, 구역 이름 앞의 동네(예: "대연5"의 "대연")가 사무실 주소에 있을 때만 잇는다.
4. 경계 하나에 구역 하나, 구역 하나에 경계 하나. 좌표 → 이름 → 사무실 순이다.
5. 매일 정비사업 동기화가 끝나면 다시 잇는다(새 구역·좌표 변화 반영).

지번 좌표: 위치가 "대연6동 1595번지"처럼 행정동으로 적혀 있으면 지번 주소용 법정동("대연동")으로 바꿔 지오코딩한다(부산 법정동 이름에는 "숫자+동"이 없다).

## 위치 보강

좌표가 없는 우리 구역이 경계와 이어지면, 그 경계 안의 대표점(`ST_PointOnSurface`)을 마커 위치로 쓴다. 이때 `location_precise`는 false이고 `position_source = "zone"`이다.

## API

- `GET /redevelopment-zones?bbox=&zoom=`: 화면 안의 경계(최대 300개). 줌에 맞춰 단순화한 GeoJSON `geometry`, `name`, `notice`, `designated_on`, 이어진 우리 구역(`redevelopment_id`, `area_name`, `kind`, `stage`)을 준다. 경계 파일을 싣기 전이면 503 `DATA_NOT_READY`.
- `GET /redevelopments`: 응답에 `zone_id`, `position_source`(`lot`/`zone`/`none`)를 더한다. bbox 필터와 lat/lng는 자기 좌표, 없으면 경계 대표점을 쓴다.

## 화면 (프론트)

- 재개발 레이어를 켜면 경계를 주황 계열 면(옅게)과 대각선 빗금으로 칠한다. 학구도(파랑 계열, 빗금 없음)와 구분된다. 카카오 지도 다각형은 무늬 채우기가 없어서, 빗금은 구역 안으로 잘라 낸 사선(Polyline)으로 그린다.
- 경계를 누르면: 이어진 구역이면 지금의 재개발 상세 시트, 아니면 "정비구역 · 이름(또는 고시번호) · 고시일 · 출처" 짧은 시트.
- 마커는 지금처럼 보이고, 위치 보강으로 수가 늘어난다.

## 하지 않는 것

- 경계 파일 자동 수집(브이월드 로그인 필요). 갱신은 파일을 다시 받아 `python -m app.ingestion redevelopment-zones`로 싣는다.
